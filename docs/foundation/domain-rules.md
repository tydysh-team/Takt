# Sprint 3 — Domain rules

## Homework lifecycle

Канонический документальный lifecycle Sprint 3:

```text
assigned
   ↓ submit
submitted
   ├─→ reviewed
   └─→ needs_revision
            ↓ resubmit
         submitted
```

- `assigned` — задание назначено и доступно Student для выполнения.
- `submitted` — существует актуальная отправленная попытка, ожидающая решения Teacher.
- `needs_revision` — Teacher вернул актуальную попытку на доработку.
- `reviewed` — актуальная попытка принята/оценена; цикл задания завершён.
- `overdue` — вычисляемый признак относительно `due_at`, а не самостоятельный lifecycle-status.

Если код использует иные буквальные имена статусов (`graded`, `in_review` и т.п.), перед merge документации необходимо выбрать один канонический набор и синхронизировать Backend, Frontend и документацию.

## Submission Attempt

- Каждая сдача создаёт отдельную попытку.
- Первая попытка имеет `attempt_no = 1`.
- Повторная отправка создаёт `attempt_no = previous + 1`.
- Исторические попытки не перезаписываются новой.
- В один момент времени у Homework не должно существовать двух конкурентных актуальных попыток одного номера.
- `submitted_at` фиксируется Backend.
- Late-признак вычисляется относительно `due_at`; историческое значение попытки после создания не переписывается.

## Ownership

- Teacher работает только с Homework/Student, доступными в его учебном контексте.
- Student получает только собственные Homework, submissions и progress data.
- Frontend-фильтрация не заменяет Backend authorization.

## Review

- Review относится к конкретной Submission Attempt.
- Для одной попытки не должно появляться несколько независимых актуальных review results от повторного сохранения одного действия.
- Возврат на доработку требует содержательного комментария Teacher.

## Statistics

- Отсутствие данных не равно нулевому результату там, где знаменатель равен нулю: процент возвращается как `null`/N/A, а не искусственный `0%`.
- Повторные attempts одного Homework не увеличивают число назначенных Homework.
- Cancelled Lesson не входит в знаменатель посещаемости.
- Attendance `not_set` не равен `absent`.
- Сводный прогресс состоит из объяснимых показателей; непрозрачный интегральный score не вводится без отдельного продуктового решения.
