# Takt — Foundation Acceptance Criteria

Документ фиксирует критерии приёмки Foundation в части, где требуется QA / Product Review / Product Acceptance.

Общие правила проведения приёмки определены в [`../general/acceptance-process.md`](../general/acceptance-process.md).

## F-06 — Teacher / Student / Authentication

### AC-F06-01 — Регистрация и роли

Система позволяет зарегистрировать пользователя как `TEACHER` или `STUDENT`.

При успешной регистрации:

- создаётся пользователь с выбранной ролью;
- возвращаются корректные пользовательские данные;
- пароль не возвращается в открытом виде.

Некорректные обязательные данные должны приводить к отказу регистрации.

### AC-F06-02 — Уникальность пользователя

Email используется как идентификатор входа.

Повторная регистрация пользователя с тем же нормализованным email не должна создавать вторую учётную запись.

### AC-F06-03 — Аутентификация

Зарегистрированный пользователь может успешно войти с корректными credentials.

Неверные credentials не должны приводить к успешной аутентификации или раскрывать лишнюю информацию о существовании пользователя.

### AC-F06-04 — Current User

Для аутентифицированного пользователя Backend предоставляет корректный текущий пользовательский контекст:

- `id`;
- роль;
- email;
- человекочитаемые данные профиля.

Текущий пользователь определяется Backend из authentication context, а не произвольным идентификатором клиента.

### AC-F06-05 — Защищённые операции

Операция, требующая аутентификации, не выполняется от имени пользователя при отсутствии действующего authentication context.

Подмена клиентского идентификатора не должна предоставлять права другого пользователя.

### AC-F06-06 — Teacher ↔ Student и demo data

В воспроизводимом окружении доступны данные, позволяющие проверить:

- Teacher;
- несколько Students;
- доступного текущему Teacher Student;
- Student, недоступного текущему Teacher.

Сценарии, использующие Teacher ↔ Student relation, должны учитывать её актуальное состояние.

## F-07 — UI/UX base

### AC-F07-01 — Единая UI/UX-основа

Для пользовательских сценариев существует согласованная UI/UX-основа с понятной структурой, типографикой и основными визуальными правилами.

### AC-F07-02 — Базовые элементы и состояния

Для применимых сценариев предусмотрены необходимые элементы интерфейса и состояния:

- input / select / button;
- выбор даты и времени;
- loading;
- error;
- empty;
- success.

### AC-F07-03 — Человекочитаемое представление

Teacher и Student отображаются пользователю человекочитаемо.

Технический идентификатор не используется как единственная пользовательская подпись.

### AC-F07-04 — Пригодность для пользовательских сценариев

UI/UX-основа не блокирует реализацию обязательных пользовательских сценариев и доступна Frontend-разработчикам в актуальном виде.

Конкретная техническая реализация компонентов не является предметом Product Review.

## F-08 — Frontend ↔ Backend Integration

### AC-F08-01 — Реальный интеграционный flow

Frontend взаимодействует с реальным Backend.

Mock-only flow не считается подтверждением готовой интеграции.

### AC-F08-02 — Authentication flow

Через пользовательский интерфейс воспроизводится сценарий:

```text
login
→ Backend authentication
→ получение текущего пользователя
→ отображение корректного пользовательского состояния
```

### AC-F08-03 — Trusted user context

Backend самостоятельно определяет текущего пользователя и его права из authentication context.

Frontend не может выполнить защищённую операцию от имени другого пользователя простой подменой идентификатора.

### AC-F08-04 — Обработка результата

Frontend корректно обрабатывает:

- успешный Backend response;
- ожидаемую Backend error;
- отсутствие действующей authentication;
- integration / transport error.

Ошибка не должна отображаться как успешная операция.

### AC-F08-05 — Воспроизводимость интеграции

Frontend и Backend могут быть воспроизводимо запущены и работают через согласованный API-контур.

Интеграция не должна зависеть от mock-данных или случайной локальной конфигурации конкретного разработчика.

---

## Результат Foundation Acceptance

Foundation Acceptance считается успешным, если:

- все применимые AC `F-06`, `F-07`, `F-08` выполнены;
- обязательные пользовательские Foundation-сценарии воспроизводятся;
- нет критических дефектов, нарушающих authentication, authorization, пользовательский контекст или FE ↔ BE integration.

Внутренняя архитектура, структура кода, БД, ORM, migrations, используемые библиотеки и другие технические решения оцениваются разработчиками и Code Review и не являются предметом повторного QA / Product Acceptance.
