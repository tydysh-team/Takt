# Ветки, коммиты и Pull Request

[К справочнику](../README.md) · [Code Review](code-review.md)

`main` — интеграционная / стабильная ветка. Обычная работа идёт в отдельных ветках; прямые рабочие коммиты в main не допускаются. Изменения достигают main через PR с review до merge.

Примеры имён:

- `feature/f-03-backend-init`
- `feature/us01-t03-create-lesson-api`
- `fix/lesson-timezone-validation`
- `docs/api-contracts`

Ветка описывает задачу, а не человека. При общей интеграции feature-веток сначала согласовать зависимости; не переключать чужой worktree или переписывать опубликованную историю без договорённости.

## Коммит и PR

Commit message кратко описывает результат, например `docs: complete F-01 project documentation`. Связанные изменения допускают один commit; количество не заменяет качество diff. Не включать случайные файлы, секреты, локальное окружение или несвязанные изменения.

PR содержит summary, scope, проверенные сценарии / команды и результаты, ссылку на задачу / US / Foundation, API / DB / UI impact, blockers и breaking changes, если есть. Автор сначала сам читает diff и проверяет, что удалённые / добавленные файлы намеренны. Документация проходит review как код.

Ревьюер назначается по задаче; не считать автоматически единственного владельца области единственным возможным ревьюером. Нерешённые review comments блокируют merge. Автор отвечает на замечание или фиксирует согласованное решение; значимые изменения после review проверяются повторно.

## Перед merge

Проверить scope, завершённый review, применимые проверки, интеграцию и отсутствие блокирующих дефектов. Кто выполняет merge, определяется командой / карточкой; данная инструкция не назначает нового merge-owner.

Для текущего проекта не объявлены обязательные CI, branch protection или GitHub Actions. Проверки выполнять доступными средствами и прикладывать результат; отсутствие автоматического enforcement не отменяет правила review. После merge обновить состояние задачи в Kaiten, не отмечая невыполненную QA / Product Acceptance как завершённую.
