# Definition of Ready / Definition of Done

[К справочнику](../README.md) · [Technical Task](../templates/technical-task.md)

## Definition of Ready для технической задачи

До активной разработки должны быть известны применимые пункты:

- ID, цель, тип и родительская US / Foundation.
- Scope и out-of-scope, проверяемые Acceptance Criteria.
- Назначенный owner, reviewer, применимые QA / Product Review.
- Зависимости и состояние блокеров, оценка SP.
- Ссылки на актуальные BR и открытые решения.
- Согласованный API-контракт для изменения обмена.
- UX/UI-решения / дизайн для затронутого интерфейса.
- Влияние на данные, миграции и demo data, если применимо.
- Ожидаемые проверки и evidence результата.

Неприменимый пункт помечается с причиной. Неопределённый обязательный контракт или продуктовый blocker не заменяется «исполнитель решит». I-выбор можно включить в scope технической задачи, если интерфейс не зависит от неизвестного продукта. Справочник не подтверждает наличие owner / reviewer / SP в конкретных карточках: это проверяется в Kaiten.

## Definition of Done

- Результат реализован / подготовлен в согласованном scope; AC проверены.
- Применимые локальные проверки прошли, результаты воспроизводимы.
- Применимые автоматические тесты добавлены / обновлены и выполнены.
- Секреты и жёстко заданная environment config отсутствуют.
- Review завершён, замечания обработаны.
- Интеграция проверена там, где затрагивается граница систем.
- QA и Product Acceptance завершены, где применимы.
- Каноническая документация и зависимые артефакты обновлены.
- Blocker / Critical дефекты, мешающие приёмке, устранены и перепроверены.
- Ссылки на evidence и фактический статус зафиксированы.

DoD не заставляет выполнять нерелевантные проверки: документационная задача проверяет ссылки, consistency и diff; дизайн — сценарии, состояния и Design Review; QA-задача — набор проверок и результаты. Код проверяет применимые unit / API / persistence / integration границы. Пометка «не применяется» не равна успешной проверке.

Major-дефект, нарушающий AC, тоже блокирует приёмку конкретной задачи. Остаточный Minor или иной согласованный неблокирующий дефект требует зарегистрированной карточки и решения PO; не скрывать его снижением severity.

Общие DoR / DoD каноничны здесь; задача дополняет их специфичными проверками, не копирует весь текст и не ослабляет требования молча.
