# Takt: запуск после клонирования с GitHub

Инструкция для локального запуска через Docker Compose в Windows PowerShell. Для Linux/macOS замените `Copy-Item .env.example .env` на `cp .env.example .env`; остальные команды Docker Compose те же.

> **Статус 2FA.** На момент написания инструкции реализация 2FA есть только в локальных незакоммиченных изменениях и ещё не опубликована на GitHub. После обычного клонирования она появится лишь тогда, когда соответствующий код будет опубликован в выбранной ветке. Публикация изменений в этой инструкции не выполняется.

## 1. Требования и клонирование

Установите Git и Docker Desktop с поддержкой `docker compose`. Запустите Docker Desktop. Для запуска приложения внутри контейнеров локальные Python и Node.js не нужны.

```powershell
git clone https://github.com/tydysh-team/Takt.git
cd Takt
```

Если код 2FA опубликован не в ветке по умолчанию, переключитесь на **опубликованную** ветку с ним: `git switch <имя-ветки>`. Проверьте наличие миграции и экрана:

```powershell
Test-Path backend\alembic\versions\20261031_0010_totp_mfa.py
Test-Path frontend\src\features\auth\MfaSettings.tsx
```

Обе команды должны вернуть `True`. Если хотя бы одна вернула `False`, выбранная ветка не содержит полную реализацию 2FA; настройка ключей сама по себе её не добавит.

## 2. Локальная конфигурация

```powershell
Copy-Item .env.example .env
```

Откройте корневой `.env` и задайте собственный `POSTGRES_PASSWORD`. Тот же пароль укажите в `DATABASE_URL` (адрес внутри Docker — `postgres`, не `localhost`):

```dotenv
POSTGRES_DB=takt
POSTGRES_USER=takt
POSTGRES_PASSWORD=<ваш-случайный-пароль>
DATABASE_URL=postgresql+asyncpg://takt:<тот-же-пароль>@postgres:5432/takt
```

Для простоты используйте в пароле БД случайные буквы и цифры. Специальные символы в `DATABASE_URL` нужно URL-кодировать. `TEST_DATABASE_URL` нужен только для отдельной тестовой БД: **не направляйте тесты на основную БД**.

Соберите Backend, затем сгенерируйте независимые ключи его криптографическим генератором:

```powershell
docker compose build backend
docker compose run --rm --no-deps backend python -c "import secrets; from cryptography.fernet import Fernet; names=('JWT_SECRET_KEY','REFRESH_TOKEN_HMAC_KEY','RATE_LIMIT_HMAC_KEY','INVITATION_CODE_SECRET','ADMIN_SESSION_SECRET','MFA_BACKUP_HMAC_KEY'); [print(name+'='+secrets.token_urlsafe(48)) for name in names]; print('TOTP_ENCRYPTION_KEY='+Fernet.generate_key().decode())"
```

Замените в `.env` пять одноимённых placeholder-значений и добавьте две строки `MFA_BACKUP_HMAC_KEY` и `TOTP_ENCRYPTION_KEY` из вывода. Не используйте один ключ для разных переменных. Вывод содержит секреты: не отправляйте его в чат или логи, не коммитьте `.env`, храните ключи в защищённом месте. **После включения 2FA не меняйте и не теряйте ключи:** иначе существующие TOTP-записи или резервные коды перестанут работать.

Для стандартного локального запуска оставьте `APP_ENV=development`, `CORS_ORIGINS=["http://localhost:5173"]` и `VITE_API_BASE_URL=http://localhost:8000`. При изменении портов согласованно обновите эти адреса.

Если на компьютере уже существует Docker volume `takt_postgres_data`, это не чистая установка: PostgreSQL сохраняет прежние учётные данные и данные. Не меняйте пароль только в `.env` и не удаляйте volume ради запуска; сначала разберитесь с существующей БД и сделайте резервную копию.

## 3. Запуск и проверка сервисов

```powershell
docker compose config --quiet
docker compose up -d --build
docker compose ps
docker compose exec backend alembic current
```

PostgreSQL, Backend и Frontend должны стать `healthy`. Backend при каждом старте автоматически выполняет `alembic upgrade head` для БД из `DATABASE_URL`. Для ветки с 2FA `alembic current` должен показать `20261031_0010`. На существующей БД **сделайте резервную копию до запуска обновлённого Backend**.

Проверьте адреса:

- Приложение: <http://localhost:5173>
- Backend: <http://localhost:8000/health>
- Swagger: <http://localhost:8000/api/docs>

Если сервис не стал `healthy`, посмотрите последние сообщения: `docker compose logs --tail=100 backend` или аналогично для `postgres`/`frontend`. Команды `docker compose down -v` и `docker volume rm` удалят данные БД — не используйте их для устранения ошибки запуска.

## 4. Первый вход для локальной разработки

На **новой** development-БД демопользователи не создаются автоматически. При необходимости выполните один раз:

```powershell
docker compose exec backend python -m app.seed
```

Скрипт разрешён только при `APP_ENV=development`; не запускайте его на рабочей БД. Для проверки интерфейса войдите как `teacher@demo.example.com` с паролем `TaktDemo!2026`. Есть также `student1@demo.example.com`; общий демонстрационный пароль тот же. Демопароль предназначен только для локальной разработки — перед проверкой безопасности смените его через настройки профиля или используйте собственную учётную запись.

## 5. Подключение и проверка 2FA

1. Откройте «Профиль → Безопасность → 2FA». До настройки статус — «Не подключена».
2. Нажмите «Подключить Authenticator», введите текущий пароль и отсканируйте QR-код приложением для одноразовых кодов. Если сканирование недоступно, введите показанный секрет вручную. Не публикуйте QR-код и секрет.
3. Введите шестизначный код и подтвердите подключение в течение 10 минут. Сохраните показанные **10 резервных кодов** вне приложения: они отображаются один раз, каждый используется один раз.
4. Подтвердите сохранение кодов. Текущая сессия завершится. В новом окне браузера войдите по паролю: сначала должен появиться запрос второго фактора, а доступ к приложению — только после верного кода.
5. Проверьте отрицательные сценарии: неверный TOTP-код отклоняется; использованный резервный код нельзя применить повторно. Один новый резервный код должен позволить войти.
6. При необходимости проверьте в настройках перевыпуск резервных кодов (старые сразу перестают действовать) и отключение 2FA. Обе операции требуют текущий пароль и код Authenticator либо резервный код.

Если код не принимается, включите автоматическую синхронизацию времени на телефоне. Если настройка 2FA недоступна, проверьте наличие обеих MFA-переменных в `.env`, пересоздание Backend после изменения `.env` и ревизию миграции. Не выводите значения ключей в диагностические логи.

## 6. Остановка

```powershell
docker compose down
```

Обычный `down` останавливает контейнеры и сохраняет PostgreSQL volume. При следующем запуске используйте `docker compose up -d` или `docker compose up -d --build` после обновления кода.
