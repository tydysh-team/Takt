# Глоссарий

[К справочнику](README.md)

Русское название и английский идентификатор обозначают одно понятие. DTO и JSON-поля не заменяют определения предметной области.

| Термин | Определение |
| --- | --- |
| Takt | Многопользовательская платформа для организации учебного процесса частных преподавателей и учеников. |
| Пользователь (User) | Человек, работающий с платформой. |
| Учётная запись (Account) | Аутентифицируемая личность пользователя. Не тождественна Teacher или Student. |
| Роль (Role) | Набор полномочий пользователя; текущие доменные роли — Teacher и Student. Политика выдачи и совмещения — Q-07. |
| Преподаватель (Teacher) | Доменные данные пользователя, который создаёт занятия для доступных ему Student и просматривает свой календарь. |
| Ученик (Student) | Доменные данные пользователя, который просматривает свои предстоящие занятия. |
| Связь Teacher–Student | Существующая связь, делающая Student доступным конкретному Teacher для планирования Lesson. |
| Занятие (Lesson) | Запланированная встреча одного Teacher и одного Student с моментом начала `starts_at`. |
| Расписание (Schedule) | Совокупность доступных пользователю занятий; не предполагает отдельную таблицу. |
| Предстоящее занятие (Upcoming Lesson) | Занятие текущего Student с `starts_at >= now`, где Backend фиксирует `now` один раз для запроса. BR-05 задаёт каноническое правило. |
| Календарный период (Calendar Period) | Диапазон абсолютных моментов времени `[from, to)`; начало включено, конец исключён. BR-07 задаёт правило выборки. |
| Аутентификация (Authentication) | Проверка личности и получение доверенного контекста Account. |
| Авторизация (Authorization) | Проверка, разрешено ли определённому Account действие над конкретным ресурсом. Токен сам по себе не даёт доступ к чужим данным. |
| Демонстрационные данные (Demo Data) | Воспроизводимые синтетические данные для демонстрации и проверки. |
| API Contract | Согласованный метод, путь, DTO, HTTP-коды, ошибки и семантика операции на границе Frontend / Backend. |
| DTO | Структура данных обмена. Не автоматическая копия ORM-модели. |
| Business Rule (BR) | Проверяемое правило предметной области со стабильным ID и источником требования. |
| Acceptance Criteria (AC) | Проверяемые условия результата конкретной истории или задачи. |
| Definition of Ready (DoR) | Условия достаточной определённости задачи для начала активной разработки. |
| Definition of Done (DoD) | Условия завершения задачи с применимыми проверками качества. |
| Product Acceptance | Подтверждение Product Owner, что результат отвечает согласованному пользовательскому поведению и границам. |
| Story Point (SP) | Относительная оценка объёма работ, не количество часов. |
| User Story (US) | Пользовательский результат; технические действия сами по себе не являются US. |
| Technical Task | Конкретная работа с владельцем, родительской US / F-задачей, критериями и оценкой. |
| Foundation task | Организационная или техническая основа проекта, обозначаемая F-ID. |
| ADR | Запись существенного архитектурного решения, контекста, альтернатив и последствий. |

Статусы решений — в [реестре](requirements/business-rules.md#открытые-решения), условия DoR / DoD — в [процессе](process/definition-of-ready-done.md).
