## Принятые baselines этой спецификации

Решения ниже основаны на заданном стеке и текущем контуре. Это целевые соглашения для реализации, а не описание готового кода. Полный текст правила находится только в указанном источнике.

| ID | Решение / основание | Канонический источник |
| --- | --- | --- |
| E-01 | Модульный монолит: достаточен для четырёх человек и текущих сценариев | [Архитектура](../overview.md) |
| E-02 | `/api/v1`, JSON UTF-8, `snake_case`, единая политика HTTP | [API conventions](../../api/conventions.md) |
| E-03 | Абсолютные моменты, UTC, полуоткрытые диапазоны; стабильные границы интеграции | [Время](../../api/conventions.md#даты-и-время), [BR-05 / BR-07](../../requirements/business-rules.md) |
| E-04 | Общая ошибка с машинным code; UI не зависит от текста и FastAPI default shape | [Error model](../../api/errors.md) |
| E-05 | API / DTO / services / persistence; UI через API-layer | [Backend](../backend.md), [Frontend](../frontend.md) |
| E-06 | UUID и минимальная модель Lesson; единый формат ID без лишних продуктовых полей | [Модель данных](../data-model.md) |
| E-07 | Bearer header и доверенный Backend context; токен непрозрачен клиенту | [Authentication](../../api/authentication.md) |

Эти baselines приняты для текущего документа по заданию; не означают отдельную проведённую командой церемонию утверждения. Изменение проходит техническое ревью и, если меняет продукт, решение PO.

## Когда нужен ADR

ADR фиксирует существенное решение с альтернативами и последствиями: стратегия аутентификации, изменение timezone-стратегии, границ модулей, библиотека состояния Frontend, замена технологии, API compatibility. Не писать ADR для каждого имени файла или поля.

Автор — инициатор технического изменения; Backend / Frontend owner проверяет свою область, PO участвует при изменении требований. Статусы: предложено → принято; либо отклонено. Принятое решение можно заменить новым ADR, сохранив ссылку и статус «заменено».

Файл именуется `NNNN-краткая-тема.md`, номер не переиспользуется. Запись содержит контекст, решение, альтернативы, последствия, проверку и затронутые документы. После принятия обновляются канонические правила и задачи; ADR не заменяет API-контракт или BR.

Отдельные нумерованные ADR пока не созданы: существенные ещё не принятые выборы I-01–I-03 находятся в [реестре решений](../../requirements/business-rules.md#открытые-решения).
