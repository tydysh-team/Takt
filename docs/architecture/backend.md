# Backend: границы модулей

[К архитектуре](overview.md) · [Модель данных](data-model.md)

## Организация FastAPI-приложения

Рекомендуемый layout будущего `backend/app/`:

| Раздел | Ответственность |
| --- | --- |
| `api/` | Роутеры, HTTP-вход/выход, декларация доступа, вызов сервисов |
| `schemas/` | Pydantic DTO запросов/ответов, проверка формы, типов и форматов |
| `services/` | Бизнес-сценарии, доступ к конкретным ресурсам, координация транзакционной операции |
| `models/` | SQLAlchemy-модели хранения, согласованные связи и ограничения |
| `repositories/` | Запросы и persistence; без формирования HTTP-ответов |
| `core/` | Конфигурация, аутентификация, общие обработчики ошибок |
| `db/` | Подключение, фабрика и жизненный цикл сессий |

Имена могут уточняться F-03 без изменения обязанностей. Не создавать отдельный абстрактный repository для каждой таблицы, если он не добавляет ясности. Роутер не содержит SQL или весь бизнес-сценарий; сервис не зависит от React или структуры UI.

## Валидация и доступ

DTO проверяет форму запроса. Сервис проверяет BR и авторизацию над ресурсом. Репозиторий выполняет фильтрацию по доверенному доменному контексту, а не по присланному ID текущего пользователя. Ограничения БД дополняют проверки сервиса; ошибки целостности переводятся в согласованные доменные ошибки, без выдачи SQL клиенту.

Создание Lesson и обязательные проверки выполняются в одной управляемой операции. Владелец транзакции — сервисная граница; репозитории не делают независимый commit, который разрушает атомарность. Ответ об успешном сохранении выдаётся после успешного commit; при сбое — rollback.

## Конфигурация и зависимости

Настройки БД, CORS, секреты аутентификации и окружение читаются централизованно из environment. Секреты не попадают в Git; безопасный пример конфигурации и реальные команды запуска появятся в F-03 / F-05. Ошибка обязательной конфигурации обнаруживается при запуске.

FastAPI dependencies предоставляют сессию БД, сервисы и текущий аутентифицированный контекст. Область сессии — запрос, с гарантированным закрытием. Не использовать глобальную сессию для всех пользователей. Sync / async режим выбирает Backend owner согласованно для драйвера, сессий и обработчиков (I-01), а не смешивает случайно.

## Ошибки и OpenAPI

Доменные исключения преобразуются в HTTP на API-границе. Обработчики schema validation, HTTP и неожиданных ошибок возвращают [единую модель](../api/errors.md); response validation / ошибка сериализации сервера — 500, а не клиентская 422. OpenAPI должен описывать фактические DTO и ошибки из [контрактов](../api/contracts/sprint-01.md).

## Границы тестирования

- Unit: BR и авторизация сервисов, управляемый источник времени, успех/ошибка без HTTP.
- API: реальные HTTP-запросы через тестовый клиент, DTO, коды, заголовок аутентификации и ошибка каждого типа.
- Persistence: фильтрация, внешние ключи, commit/rollback, временные границы на изолированной PostgreSQL.
- Сквозная интеграция: реальный Frontend ↔ Backend запрос и доступность сохранённого Lesson.

pytest — базовый инструмент Backend. Моки допустимы для изоляции unit-тестов, но не доказывают корректность SQL или полной интеграции.
