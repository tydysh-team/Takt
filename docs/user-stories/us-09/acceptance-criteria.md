# US-09 — Acceptance Criteria

## User Story

**Я как преподаватель хочу создавать повторяющиеся занятия, чтобы не добавлять вручную каждое регулярное занятие.**

---

## AC-US09-01 — Создание минимальной серии

**Given**
- пользователь аутентифицирован как `Teacher`;
- выбран доступный `Student`;
- параметры Lesson валидны;
- recurrence = `weekly`;
- `count = 2`;
- конфликтов нет.

**When**
- Teacher подтверждает создание серии.

**Then**
- создаются ровно 2 отдельных `Lesson`;
- первый Lesson имеет базовые дату и время;
- второй Lesson создаётся через одну календарную неделю;
- оба Lesson сохраняются Backend.

---

## AC-US09-02 — Создание обычной weekly-серии

**Given**
- `count = N`;
- `2 <= N <= 52`;
- остальные параметры валидны;
- конфликтов нет.

**When**
- Teacher создаёт серию.

**Then**
- создаются ровно `N` отдельных Lesson;
- между соседними экземплярами сохраняется weekly-периодичность;
- пропущенные или дополнительные экземпляры отсутствуют.

---

## AC-US09-03 — Создание максимальной серии

**Given**
- `count = 52`;
- остальные параметры валидны.

**Then**
- система допускает создание серии;
- создаются ровно 52 отдельных Lesson;
- серия корректно сохраняется и отображается.

---

## AC-US09-04 — Количество меньше минимального

**Given**
- `count < 2`.

**Then**
- серия не создаётся;
- отображается validation error;
- ни один Lesson не сохраняется.

---

## AC-US09-05 — Количество больше максимального

**Given**
- `count > 52`.

**Then**
- серия не создаётся;
- пользователь получает validation error;
- частичное создание отсутствует.

---

## AC-US09-06 — Weekly recurrence

Для серии с recurrence = `weekly`:

- первый экземпляр создаётся в `base_starts_at`;
- каждый следующий Lesson создаётся через одну календарную неделю;
- порядок экземпляров соответствует выбранной серии.

Формально:

`lesson[i].starts_at = base_starts_at + i calendar weeks`

для:

`i = 0 ... count - 1`.

---

## AC-US09-07 — Каждый экземпляр является отдельным Lesson

После успешного создания:

- каждый экземпляр имеет отдельный идентификатор;
- каждый экземпляр существует как самостоятельный Lesson;
- экземпляры можно отдельно получать из Backend;
- отдельный экземпляр может участвовать в US-05–US-08.

---

## AC-US09-08 — Сохранение общих данных серии

Для всех экземпляров серии сохраняются согласованные данные:

- `Student`;
- `Teacher`;
- duration;
- предмет / содержание и другие данные базового Lesson;
- параметры, которые не зависят от конкретной даты экземпляра.

Изменяться между экземплярами должны только данные, определяемые recurrence rule.

---

## AC-US09-09 — Базовая дата в прошлом

**Given**
- `base_starts_at` находится в прошлом.

**Then**
- серия не создаётся;
- возвращается validation error;
- ни один Lesson серии не сохраняется.

---

## AC-US09-10 — Некорректные обязательные параметры

Серия не должна создаваться при:

- отсутствующем Student;
- недоступном Student;
- некорректной дате;
- некорректном времени;
- недопустимой duration;
- отсутствующих обязательных данных Lesson;
- неподдерживаемом recurrence type.

При ошибке:

- сохраняется 0 новых Lesson;
- ложный success отсутствует.

---

## AC-US09-11 — Поддерживается только weekly recurrence

В рамках US-09 Sprint 2 валидным recurrence type является `weekly`.

Запросы с неподдерживаемыми правилами:

- `daily`;
- `monthly`;
- сложными recurrence expressions;
- другими несогласованными значениями

должны быть отклонены validation error.

---

## AC-US09-12 — Summary перед созданием

До окончательного создания Teacher должен видеть однозначное описание серии минимум с:

- Student;
- базовыми датой и временем;
- weekly-периодичностью;
- количеством Lesson;
- границей / последним экземпляром серии.

До подтверждения Backend не создаёт Lesson серии.

---

## AC-US09-13 — Отмена до подтверждения

**Given**
- Teacher настроил серию;
- создание ещё не подтверждено.

**When**
- пользователь отменяет сценарий.

**Then**
- новые Lesson не создаются;
- существующее расписание не изменяется;
- success-state отсутствует.

---

## AC-US09-14 — Серия без конфликтов

**Given**
- ни один экземпляр серии не пересекается с существующими Lesson текущего Teacher.

**Then**
- conflict-warning не отображается;
- после подтверждения создаётся вся серия.

---

## AC-US09-15 — Один конфликт внутри серии

**Given**
- ровно один экземпляр серии конфликтует с существующим Lesson.

**Then**
- серия не создаётся автоматически;
- Teacher получает conflict-warning;
- пользователь может определить конфликтующий экземпляр;
- warning содержит достаточные дату / время для понимания конфликта.

---

## AC-US09-16 — Несколько конфликтов внутри серии

**Given**
- конфликтуют два или более экземпляра.

**Then**
- серия не создаётся автоматически;
- warning сообщает о нескольких конфликтах;
- пользователь может определить конфликтующие даты / экземпляры;
- серия не создаётся без дальнейшего решения Teacher.

---

## AC-US09-17 — Явное подтверждение конфликтной серии

**Given**
- в серии обнаружен один или несколько конфликтов.

**When**
- Teacher явно подтверждает создание несмотря на warning.

**Then**
- создаётся вся серия;
- конфликтующие экземпляры также сохраняются;
- conflict не является hard block.

Без явного подтверждения серия не создаётся.

---

## AC-US09-18 — Изменение параметров после conflict-warning

Если после warning Teacher изменяет параметры, влияющие на расписание, например:

- дату;
- время;
- duration;
- Student;
- количество Lesson,

то:

- старый conflict-result считается неактуальным;
- перед созданием повторно проверяется вся серия;
- решение основывается только на новых параметрах.

---

## AC-US09-19 — Conflict-check только для текущего Teacher

При проверке пересечений учитываются Lesson текущего авторизованного Teacher.

Teacher определяется из authentication context.

Lesson других Teacher не должны ошибочно создавать конфликт в расписании текущего пользователя.

---

## AC-US09-20 — Атомарное создание серии

Создание серии работает по принципу:

**all-or-nothing**.

При успешной операции:

- создаются все `N` Lesson.

При ошибке:

- создаётся 0 Lesson.

Состояние, при котором создалась только часть серии из-за ошибки операции, не допускается.

---

## AC-US09-21 — Backend / API error

**When**
- во время создания возникает Backend / API / transport error.

**Then**
- операция не считается успешной;
- частично созданная серия не должна оставаться итоговым результатом;
- UI отображает error-state;
- ложный success отсутствует.

---

## AC-US09-22 — Loading-state и защита от повторной отправки

Во время активной операции:

- отображается loading-state;
- повторное подтверждение блокируется;
- несколько одинаковых серий не должны создаваться из-за повторного клика;
- success отображается только после подтверждения Backend.

---

## AC-US09-23 — Teacher определяется из authentication context

Создать серию может только текущий авторизованный `Teacher`.

Не допускается:

- создание серии от имени другого Teacher;
- изменение владельца через произвольный `teacher_id`;
- обход ownership-проверки.

---

## AC-US09-24 — Недоступный Student

**Given**
- Student не существует либо недоступен текущему Teacher.

**Then**
- серия не создаётся;
- Backend отклоняет операцию;
- сохраняется 0 новых Lesson;
- возвращается корректный authorization / validation / not-found result согласно API-контракту.

---

## AC-US09-25 — Date / Time / Timezone semantics

Для weekly-серии:

- временные значения являются timezone-aware;
- сохраняется согласованное локальное время занятия;
- изменение UTC offset не должно самопроизвольно изменять пользовательский локальный час серии;
- Backend является источником истины для сформированных временных значений.

---

## AC-US09-26 — Teacher Calendar

После успешного создания:

- все Lesson серии отображаются в расписании Teacher;
- отсутствующие экземпляры отсутствуют только если их действительно нет Backend;
- каждый Lesson отображается в соответствующем временном слоте;
- расписание обновляется без ручного `F5`.

---

## AC-US09-27 — Student Calendar

После успешного создания соответствующий Student видит все Lesson серии.

Количество, даты и время в расписании Student должны соответствовать расписанию Teacher.

---

## AC-US09-28 — Серия через несколько недель / периодов

Если серия охватывает несколько:

- недель;
- календарных представлений;
- месяцев,

то каждый экземпляр отображается в соответствующем периоде.

Переключение календарного диапазона не должно приводить к потере Lesson.

---

## AC-US09-29 — Отсутствие дублей

После успешного создания:

- один экземпляр серии соответствует одному Lesson;
- повторное получение данных не создаёт дополнительных Lesson;
- переключение календаря не создаёт дубли;
- refresh не увеличивает количество записей.

---

## AC-US09-30 — Persistence after refresh

**Given**
- серия была успешно создана.

**When**
- пользователь обновляет страницу или повторно получает расписание.

**Then**
- все созданные Lesson сохраняются;
- количество экземпляров не меняется;
- даты и время соответствуют Backend;
- Teacher и Student получают тот же актуальный набор.

---

## AC-US09-31 — Реальный Frontend ↔ Backend E2E

Необходимо подтвердить end-to-end сценарий без mock-response:

1. Teacher открывает создание Lesson;
2. включает repeat;
3. выбирает `weekly`;
4. задаёт `count`;
5. Frontend валидирует параметры;
6. пользователю показывается summary;
7. Frontend отправляет запрос;
8. Backend проверяет auth и Student;
9. Backend генерирует даты;
10. каждый экземпляр проходит conflict-check;
11. при необходимости выполняется warning / confirmation flow;
12. Backend атомарно создаёт серию;
13. Frontend получает результат;
14. Calendar Teacher обновляется;
15. Student получает тот же набор Lesson;
16. после refresh результат сохраняется.

---

## AC-US09-32 — Отдельный Lesson после создания серии

После успешного создания любой отдельный экземпляр должен корректно работать со связанными сценариями:

- US-05 — перенос;
- US-06 — отмена;
- US-07 — статус;
- US-08 — attendance.

Обработка одного Lesson не должна автоматически менять остальные экземпляры серии.

---

## AC-US09-33 — Regression связанных сценариев

После внедрения US-09 должны сохранять работоспособность:

- `US-01` — создание одиночного Lesson;
- `US-02` — расписание Student;
- `US-03` — календарь Teacher;
- `US-04` — conflict-flow;
- `US-05` — перенос;
- `US-06` — отмена;
- `US-07` — статус;
- `US-08` — attendance.

Обычное создание одиночного Lesson не должно требовать включения recurrence.

---

# Обязательные Acceptance Criteria

Для Product Acceptance обязательными являются:

- `AC-US09-01` — минимальная серия;
- `AC-US09-02` — обычная серия;
- `AC-US09-03` — максимальная серия;
- `AC-US09-04` — ниже минимума;
- `AC-US09-05` — выше максимума;
- `AC-US09-06` — weekly recurrence;
- `AC-US09-07` — отдельные Lesson;
- `AC-US09-08` — сохранение общих данных;
- `AC-US09-09` — past date;
- `AC-US09-10` — invalid parameters;
- `AC-US09-11` — supported recurrence;
- `AC-US09-12` — summary;
- `AC-US09-13` — cancel before confirmation;
- `AC-US09-14` — no conflict;
- `AC-US09-15` — one conflict;
- `AC-US09-16` — multiple conflicts;
- `AC-US09-17` — explicit conflict confirmation;
- `AC-US09-18` — recheck after change;
- `AC-US09-19` — current Teacher conflict scope;
- `AC-US09-20` — atomicity;
- `AC-US09-21` — API error;
- `AC-US09-22` — loading / duplicate protection;
- `AC-US09-23` — authentication ownership;
- `AC-US09-24` — unavailable Student;
- `AC-US09-25` — timezone;
- `AC-US09-26` — Teacher Calendar;
- `AC-US09-27` — Student Calendar;
- `AC-US09-28` — cross-period series;
- `AC-US09-29` — no duplicates;
- `AC-US09-30` — persistence;
- `AC-US09-31` — Frontend ↔ Backend E2E;
- `AC-US09-32` — отдельный Lesson после создания;
- `AC-US09-33` — regression.

Если хотя бы один обязательный Acceptance Criterion имеет статус `FAIL`, итоговый статус US-09 не может быть `PASS`.
