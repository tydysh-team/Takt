# US-03 — Acceptance Criteria

Общие правила QA / Product Acceptance определены в [`../../general/acceptance-process.md`](../../general/acceptance-process.md).

## AC-US03-01 — Расписание текущего Teacher

**Given:** пользователь аутентифицирован как `TEACHER`.

**When:** открывается расписание.

**Then:**

- загружаются занятия текущего Teacher;
- занятия других Teachers не попадают в результат;
- текущий Teacher определяется Backend из authentication context.

## AC-US03-02 — Данные занятия

Для каждого занятия отображаются минимум:

- название;
- Student;
- дата и время начала;
- длительность.

## AC-US03-03 — Человекочитаемый Student

Student отображается пользователю человекочитаемо.

Технический идентификатор не используется как единственная подпись ученика.

## AC-US03-04 — Фильтрация по периоду

Frontend может запрашивать занятия за выбранный временной диапазон.

Backend возвращает только занятия:

- доступные текущему Teacher;
- попадающие в запрошенный период.

Некорректный диапазон дат не должен считаться успешным запросом.

## AC-US03-05 — Режим «Неделя»

В режиме `Неделя`:

- отображаются дни недели;
- занятия расположены в соответствии со своей датой и временем;
- для занятия отображаются основные пользовательские данные.

## AC-US03-06 — Режим «Список»

В режиме `Список`:

- Teacher может выбрать день;
- отображаются занятия выбранного дня;
- при отсутствии занятий показывается понятное empty state.

## AC-US03-07 — Переключение недель

Teacher может переключать предыдущую и следующую неделю.

После переключения отображается расписание соответствующего периода.

Переключение недели само по себе не изменяет занятия.

## AC-US03-08 — Пользовательские состояния

Интерфейс корректно обрабатывает:

- loading;
- empty;
- Backend / API error;
- успешную загрузку.

Ошибка получения данных не должна отображаться как успешное пустое расписание.

## AC-US03-09 — Доступ к чужому расписанию

Frontend не может получить расписание другого Teacher простой подменой `teacher_id`.

Scope доступных занятий определяется Backend на основании текущего пользователя.

## AC-US03-10 — Границы сценария

Просмотр календаря не должен сам по себе:

- переносить Lesson;
- отменять Lesson;
- изменять статус Lesson;
- изменять Teacher или Student занятия.

Создание нового Lesson относится к US-01.

## Результат Acceptance

`US-03 = PASS`, если:

- все применимые `AC-US03-01–AC-US03-10` выполнены;
- Teacher видит своё расписание за выбранный период;
- данные других Teachers не раскрываются;
- режимы `Неделя` и `Список` работают без критических дефектов.

`US-03 = FAIL`, если хотя бы один обязательный Acceptance Criterion не выполнен.

`US-03 = BLOCKED`, если проверку невозможно завершить из-за отсутствующего окружения, данных или другого внешнего blocker.
