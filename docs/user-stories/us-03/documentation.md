# US-03 — Календарь преподавателя

## User Story

> Я как преподаватель хочу видеть своё расписание занятий, чтобы понимать свою загрузку и запланированные уроки.

## 1. Пользовательский результат

Аутентифицированный `Teacher` может открыть расписание и увидеть занятия, относящиеся к нему.

Для каждого занятия отображается информация, достаточная для понимания:

- что за занятие запланировано;
- с каким Student;
- когда оно начинается;
- сколько длится.

## 2. Основной сценарий

1. Teacher открывает расписание.
2. Система определяет текущего пользователя из authentication context.
3. Загружает занятия текущего Teacher за отображаемый период.
4. Teacher видит своё расписание.
5. Пользователь может просматривать занятия в режимах:
   - `Неделя`;
   - `Список`.
6. В режиме списка можно выбрать конкретный день.
7. Пользователь может переключаться между неделями.

## 3. Отображение занятия

Для занятия отображается минимум:

- название;
- Student;
- дата и время;
- длительность.

Student отображается человекочитаемо.

Технический идентификатор не используется как единственная пользовательская подпись.

## 4. Доступ к данным

Teacher должен видеть только занятия, доступные текущему пользователю.

Текущий Teacher определяется Backend из authentication context.

Frontend не передаёт произвольный `teacher_id`, чтобы получить расписание другого Teacher.

## 5. Получение занятий

Для получения расписания используется:

```text
POST /api/v1/lessons/search
```

Запрос может содержать временной диапазон:

```json
{
  "date_from": "2026-10-19T00:00:00Z",
  "date_to": "2026-10-26T00:00:00Z"
}
```

Backend возвращает занятия текущего Teacher, попадающие в выбранный период.

Общие API-правила определены в [`../../general/api-conventions.md`](../../general/api-conventions.md).

## 6. Представление расписания

### Неделя

В недельном режиме:

- отображаются семь дней недели;
- занятия располагаются в соответствии со своей датой и временем;
- для занятия показываются название, Student и время.

### Список

В режиме списка:

- Teacher выбирает день;
- отображаются занятия выбранного дня;
- для каждого занятия показываются основные данные.

Если на выбранный день занятий нет, отображается понятное empty state.

## 7. Переключение недель

Teacher может просматривать предыдущие и следующие недели.

При переключении недели изменяется временной диапазон загружаемого расписания.

Навигация не изменяет сами занятия.

## 8. Пользовательские состояния

Интерфейс должен корректно обрабатывать:

- loading;
- empty;
- Backend / API error;
- успешную загрузку расписания.

Ошибка загрузки не должна отображаться как корректное пустое расписание.

## 9. Границы US-03

US-03 отвечает за просмотр календаря Teacher.

Изменение уже существующих занятий, включая:

- перенос;
- отмену;
- изменение статуса;
- работу с конфликтами расписания;

относится к отдельным User Story.

Создание нового Lesson определяется US-01.

Внутренняя реализация поиска, структура БД, repositories, state management и другие технические решения определяются разработчиками и Code Review.
