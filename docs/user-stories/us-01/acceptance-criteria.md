# US-01 — Acceptance Criteria

Общие правила QA / Product Acceptance определены в [`../../general/acceptance-process.md`](../../general/acceptance-process.md).

## AC-US01-01 — Доступные Students

**Given:** пользователь аутентифицирован как `Teacher`.

**When:** открывается сценарий создания занятия.

**Then:**

- отображаются Students, доступные текущему Teacher;
- Student представлен человекочитаемо;
- отсутствие доступных Students является корректным состоянием.

## AC-US01-02 — Обязательные данные

Для создания занятия обязательны:

- Student;
- название;
- дата;
- время начала;
- длительность.

Описание является необязательным.

Без обязательных данных занятие не создаётся.

## AC-US01-03 — Валидация данных

Система отклоняет некорректные данные, включая применимые случаи:

- некорректный `student_id`;
- пустое название;
- название длиннее 120 символов;
- описание длиннее 2000 символов;
- некорректную дату или время;
- отсутствие timezone / offset во внешнем datetime;
- неположительную длительность.

Ошибка не должна отображаться как успешное создание.

## AC-US01-04 — Trusted Teacher

Teacher создаваемого Lesson определяется Backend из текущего authentication context.

Клиент не может создать Lesson от имени другого Teacher простой подменой идентификатора.

## AC-US01-05 — Доступность Student

На момент создания Student должен быть доступен текущему Teacher через актуальную `Teacher ↔ Student` relation.

Если Student:

- не существует;
- существует, но недоступен текущему Teacher;

Lesson не создаётся.

## AC-US01-06 — Время начала

Если:

```text
starts_at < Backend now
```

Lesson не создаётся.

Дата и время должны однозначно представлять момент времени с учётом timezone пользователя.

## AC-US01-07 — Успешное создание

**Given:**

- пользователь аутентифицирован как Teacher;
- выбран доступный Student;
- обязательные данные корректны;
- время начала не находится в прошлом.

**When:** Teacher подтверждает создание.

**Then:**

- создаётся один Lesson;
- Lesson связан с текущим Teacher;
- Lesson связан с выбранным Student;
- сохраняются название, описание при наличии, время начала и длительность;
- Backend возвращает успешный результат создания.

## AC-US01-08 — Результат создания

После успешного создания Lesson существует в состоянии системы и становится доступен в расписании.

Frontend обновляет отображаемое расписание без необходимости считать занятие созданным только на основании локального состояния формы.

Пользователь получает понятное подтверждение успешного создания.

## AC-US01-09 — Authentication / Authorization

Создание Lesson не выполняется, если:

- отсутствует действующая authentication;
- текущему пользователю недоступен Teacher-сценарий.

В этих случаях Lesson не создаётся.

## AC-US01-10 — Ошибочные состояния

Frontend корректно обрабатывает:

- validation error;
- Backend / API error;
- submitting state;
- success state.

Ошибка не должна приводить к ложному успешному состоянию.

## AC-US01-11 — Конфликты расписания

US-01 не требует проверки пересечений или конфликтов между занятиями.

Наличие другого Lesson в то же или пересекающееся время само по себе не является основанием для отказа в рамках US-01.

Проверка конфликтов относится к отдельной User Story.

## Результат Acceptance

`US-01 = PASS`, если:

- все применимые `AC-US01-01–AC-US01-11` выполнены;
- end-to-end сценарий создания Lesson воспроизводится;
- созданное занятие появляется в расписании;
- отсутствуют критические дефекты, нарушающие обязательный пользовательский сценарий.

`US-01 = FAIL`, если хотя бы один обязательный Acceptance Criterion не выполнен.

`US-01 = BLOCKED`, если проверку невозможно завершить из-за отсутствующего окружения, данных или другого внешнего blocker.
