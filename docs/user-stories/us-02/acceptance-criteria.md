# US-02 — Acceptance Criteria

Общие правила QA / Product Acceptance определены в [`../../general/acceptance-process.md`](../../general/acceptance-process.md).

## AC-US02-01 — Расписание текущего Student

**Given:** пользователь аутентифицирован как `STUDENT`.

**When:** открывается расписание.

**Then:**

- загружаются занятия, доступные текущему Student;
- занятия других Students не попадают в результат;
- текущий Student определяется Backend из authentication context.

## AC-US02-02 — Предстоящие занятия

В актуальном расписании Student видит свои предстоящие занятия.

Для занятия доступны минимум:

- название;
- Teacher;
- дата и время начала;
- длительность.

## AC-US02-03 — Человекочитаемый Teacher

Teacher отображается пользователю человекочитаемо.

Технический идентификатор не используется как единственная подпись преподавателя.

## AC-US02-04 — Фильтрация по периоду

Frontend может запрашивать занятия за выбранный временной диапазон.

Backend возвращает только занятия:

- доступные текущему пользователю;
- попадающие в запрошенный период.

Некорректный диапазон дат не должен считаться успешным запросом.

## AC-US02-05 — Режим «Неделя»

В режиме `Неделя`:

- отображаются дни недели;
- занятия расположены в соответствии со своей датой и временем;
- для занятия отображаются основные пользовательские данные;
- несколько Lessons, полностью или частично пересекающихся по времени, остаются различимыми и доступными для просмотра.

## AC-US02-06 — Режим «Список»

В режиме `Список`:

- пользователь может выбрать день;
- отображаются занятия выбранного дня;
- при отсутствии занятий показывается понятное empty state.

## AC-US02-07 — Переключение недель

Пользователь может переключать отображаемую неделю.

При смене недели расписание обновляется для соответствующего временного периода.

Навигация по другим неделям сама по себе не изменяет данные занятия.

## AC-US02-08 — Пользовательские состояния

Интерфейс корректно обрабатывает:

- loading;
- empty;
- Backend / API error;
- успешную загрузку.

Ошибка получения данных не должна отображаться как успешное пустое расписание.

## AC-US02-09 — Ограничение возможностей Student

В рамках US-02 Student не получает возможность через сценарий просмотра:

- создать Lesson;
- изменить Lesson;
- отменить Lesson;
- выполнить действие от имени другого пользователя.

## Результат Acceptance

`US-02 = PASS`, если:

- все применимые `AC-US02-01–AC-US02-09` выполнены;
- Student видит своё актуальное расписание;
- данные других пользователей не раскрываются;
- основные режимы просмотра воспроизводятся без критических дефектов.

`US-02 = FAIL`, если хотя бы один обязательный Acceptance Criterion не выполнен.

`US-02 = BLOCKED`, если проверку невозможно завершить из-за отсутствующего окружения, данных или другого внешнего blocker.
