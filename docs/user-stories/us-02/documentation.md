# US-02 — Просмотр предстоящих занятий учеником

## User Story

> Я как ученик хочу видеть свои предстоящие занятия, чтобы понимать своё актуальное расписание.

## 1. Пользовательский результат

Аутентифицированный `Student` может открыть расписание и увидеть занятия, относящиеся к нему.

Для каждого занятия отображается информация, достаточная для понимания:

- что за занятие запланировано;
- с каким Teacher;
- когда оно начинается;
- сколько длится.

## 2. Основной сценарий

1. Student открывает расписание.
2. Система определяет текущего пользователя из authentication context.
3. Загружает доступные ему занятия за отображаемый период.
4. Student видит своё расписание.
5. Пользователь может просматривать занятия в режимах:
   - `Неделя`;
   - `Список`.
6. В режиме списка можно выбрать конкретный день.
7. Пользователь может переключаться между неделями.

## 3. Отображение занятия

Для доступного Student занятия отображается минимум:

- название;
- Teacher;
- дата и время;
- длительность.

Teacher отображается человекочитаемо.

Технический идентификатор пользователя не используется как единственная пользовательская подпись.

## 4. Доступ к данным

Student должен видеть только занятия, относящиеся к текущему пользователю.

Текущий Student определяется Backend из authentication context.

Frontend не передаёт произвольный `student_id`, чтобы получить расписание другого пользователя.

## 5. Получение занятий

Для получения расписания используется:

```text
POST /api/v1/lessons/search
```

Запрос может содержать временной диапазон:

```json
{
  "date_from": "2026-10-23T00:00:00Z",
  "date_to": "2026-10-30T00:00:00Z"
}
```

Backend ограничивает результат занятиями, доступными текущему пользователю.

При отображении актуального расписания основным пользовательским результатом являются предстоящие занятия.

Общие API-правила определены в [`../../general/api-conventions.md`](../../general/api-conventions.md).

## 6. Представление расписания

### Неделя

В недельном режиме:

- отображаются дни недели;
- занятия располагаются в соответствии с датой и временем;
- для занятия показываются название, Teacher и время.

### Список

В режиме списка:

- пользователь выбирает день;
- занятия выбранного дня отображаются последовательным списком;
- для каждого занятия отображаются основные данные.

Если на выбранный день занятий нет, отображается понятное empty state.

## 7. Пользовательские состояния

Интерфейс должен корректно обрабатывать:

- loading;
- empty;
- Backend / API error;
- успешную загрузку расписания.

Ошибка загрузки не должна отображаться как корректное пустое расписание.

## 8. Границы US-02

US-02 не предоставляет Student возможность:

- создавать занятия;
- изменять занятия;
- переносить занятия;
- отменять занятия;
- изменять Teacher или Student занятия.

Эти действия относятся к другим User Story.

Внутренняя реализация поиска, структура БД, repositories, state management и другие технические решения определяются разработчиками и Code Review.
