# US-08 — Acceptance Criteria

## User Story

**Я как преподаватель хочу отмечать факт посещения занятия учеником, чтобы сохранять историю проведённых занятий.**

---

## AC-US08-01 — Первоначальное состояние без отметки

**Given**
- `Lesson` существует;
- attendance ранее не устанавливался.

**When**
- `Teacher` открывает доступный ему `Lesson`.

**Then**
- attendance отображается как `not_set`;
- пользователь видит человекочитаемое состояние `Не отмечено`;
- ложные значения `present` / `absent` не отображаются.

---

## AC-US08-02 — Установка Present

**Given**
- attendance доступен для изменения;
- текущее значение = `not_set`.

**When**
- `Teacher` выбирает `present`.

**Then**
- Backend сохраняет значение;
- Frontend отображает `Присутствовал`;
- значение остаётся актуальным после повторного получения данных.

---

## AC-US08-03 — Установка Absent

**Given**
- attendance доступен для изменения;
- текущее значение = `not_set`.

**When**
- `Teacher` выбирает `absent`.

**Then**
- Backend сохраняет значение;
- Frontend отображает `Отсутствовал`;
- значение сохраняется после refresh.

---

## AC-US08-04 — Изменение Present → Absent

**Given**
- текущее сохранённое значение = `present`.

**When**
- `Teacher` изменяет его на `absent`.

**Then**
- Backend сохраняет новое значение;
- `absent` становится актуальным;
- старое значение больше не отображается как текущее.

---

## AC-US08-05 — Изменение Absent → Present

**Given**
- текущее сохранённое значение = `absent`.

**When**
- `Teacher` изменяет его на `present`.

**Then**
- Backend сохраняет новое значение;
- `present` становится актуальным;
- UI отображает подтверждённое Backend-состояние.

---

## AC-US08-06 — Attendance доступен только для собственного Lesson

Изменять attendance может только текущий авторизованный `Teacher`, которому принадлежит `Lesson`.

`Teacher` определяется из authentication context.

Не допускается получение доступа через подмену `teacher_id` либо другого идентификатора владельца.

---

## AC-US08-07 — Attendance связан с конкретным Student и Lesson

Сохранённая отметка должна относиться только к конкретному `Lesson` и связанному с ним `Student`.

Изменение attendance одного занятия не должно:

- изменять другие Lesson этого Student;
- изменять attendance другого Student;
- менять связь Lesson ↔ Student.

---

## AC-US08-08 — Будущий Lesson

**Given**
- `now < starts_at`.

**Then**
- управление attendance недоступно;
- `Teacher` не может успешно сохранить `present` или `absent`;
- Backend не принимает изменение;
- ложный success отсутствует.

---

## AC-US08-09 — Точная граница начала занятия

**Given**
- `now == starts_at`;
- Lesson не отменён.

**Then**
- управление attendance становится доступным;
- `Teacher` может установить допустимое значение.

---

## AC-US08-10 — In Progress Lesson

**Given**
- Lesson находится в состоянии `in_progress`.

**Then**
- attendance доступен для установки и изменения;
- допустимые значения сохраняются Backend.

---

## AC-US08-11 — Completed Lesson

**Given**
- Lesson находится в состоянии `completed`.

**Then**
- attendance доступен;
- ранее установленное значение можно просматривать;
- изменение отметки разрешено согласно спецификации.

---

## AC-US08-12 — Cancelled Lesson

**Given**
- Lesson имеет статус `cancelled`.

**Then**
- изменение attendance недоступно;
- новое значение сохранить нельзя;
- существующее Backend-состояние Lesson не изменяется.

---

## AC-US08-13 — Перенесённый Lesson до нового времени

**Given**
- Lesson был перенесён;
- актуальный `now < new_starts_at`;
- Lesson не отменён.

**Then**
- lifecycle-status Lesson = `planned`;
- attendance недоступен;
- используется новое актуальное время занятия, а не старое;
- признак `Перенесено` не заменяет lifecycle-status `planned`.

---

## AC-US08-14 — Перенесённый Lesson после наступления нового времени

**Given**
- Lesson был перенесён;
- `now >= new_starts_at`;
- Lesson не отменён.

**Then**
- lifecycle-status определяется по актуальному новому времени как `in_progress` или `completed`;
- attendance доступен;
- `Teacher` может установить или изменить допустимое значение;
- признак `Перенесено` не используется как самостоятельный lifecycle-status.

---

## AC-US08-15 — Чужой или недоступный Lesson

**When**
- текущий `Teacher` пытается изменить attendance чужого либо недоступного Lesson.

**Then**
- операция отклоняется;
- attendance не изменяется;
- возвращается корректный authorization / not-found result;
- ложный success отсутствует.

---

## AC-US08-16 — Отсутствующий Lesson

При попытке изменить attendance несуществующего Lesson:

- операция не выполняется;
- другие данные не изменяются;
- возвращается корректный not-found result;
- success-state отсутствует.

---

## AC-US08-17 — Недопустимое attendance-значение

Backend должен принимать только согласованные значения attendance.

Некорректное или неподдерживаемое значение:

- отклоняется;
- не изменяет существующую отметку;
- возвращает validation error;
- не отображается как успешное изменение.

---

## AC-US08-18 — Backend / API error при сохранении

**Given**
- существует текущее подтверждённое значение attendance.

**When**
- изменение завершается Backend / API / transport error.

**Then**
- предыдущее подтверждённое значение сохраняется;
- новое значение не становится актуальным;
- UI отображает error-state;
- ложный success отсутствует.

---

## AC-US08-19 — Loading-state и защита от повторной отправки

Во время активного сохранения:

- отображается loading-state;
- повторное действие не должно создавать несколько конкурирующих запросов;
- новое значение не считается сохранённым до успешного ответа Backend.

---

## AC-US08-20 — Повторное открытие Lesson

**Given**
- attendance был успешно сохранён.

**When**
- `Teacher` закрывает и повторно открывает Lesson.

**Then**
- отображается последнее сохранённое Backend-значение;
- локальное состояние не подменяет фактический результат.

---

## AC-US08-21 — Persistence after refresh

После обновления страницы:

- `not_set / present / absent` отображается согласно Backend;
- сохранённая отметка не теряется;
- неподтверждённое локальное значение не восстанавливается как актуальное.

---

## AC-US08-22 — Неизвестное attendance-значение

Если Frontend получает неизвестное или неподдерживаемое значение:

- интерфейс не должен падать;
- значение не должно молча подменяться на `not_set`, `present` или `absent`;
- отображается безопасное fallback / error representation;
- ситуация может быть зафиксирована как integration defect.

---

## AC-US08-23 — Authentication / Authorization

Неаутентифицированный пользователь не должен иметь возможности читать или изменять защищённый attendance-сценарий.

Пользователь без роли `Teacher` не должен получать доступ к управлению attendance.

---

## AC-US08-24 — Реальный Frontend ↔ Backend E2E

Необходимо подтвердить end-to-end сценарий без mock-response:

1. `Teacher` открывает собственный Lesson;
2. Frontend получает текущее attendance-значение;
3. пользователь выбирает допустимое значение;
4. Frontend отправляет изменение;
5. Backend проверяет ownership, актуальный lifecycle-status Lesson и значение;
6. Backend сохраняет attendance;
7. Frontend получает подтверждённое состояние;
8. карточка Lesson обновляется;
9. после повторного открытия и refresh сохраняется то же значение.

Для перенесённого Lesson проверка выполняется по актуальным новым временным данным; признак переноса не заменяет lifecycle-status.

---

## AC-US08-25 — Ошибка не создаёт ложное UI-состояние

Во всех неуспешных сценариях:

- validation error;
- authorization error;
- Backend error;
- transport error

Frontend не должен показывать неподтверждённое значение как успешно сохранённое.

После повторного получения данных UI должен соответствовать Backend.

---

## AC-US08-26 — Regression связанных сценариев

После внедрения US-08 должны сохранять работоспособность:

- `US-01` — создание занятия;
- `US-02` — расписание Student;
- `US-03` — календарь Teacher;
- `US-04` — conflict-flow;
- `US-05` — перенос;
- `US-06` — отмена;
- `US-07` — модель lifecycle-status и отдельного признака переноса.

Attendance не должен нарушать создание, отображение, перенос, отмену и определение состояния Lesson.

---

# Обязательные Acceptance Criteria

Для Product Acceptance обязательными являются:

- `AC-US08-01` — not set;
- `AC-US08-02` — present;
- `AC-US08-03` — absent;
- `AC-US08-04` — present → absent;
- `AC-US08-05` — absent → present;
- `AC-US08-06` — ownership;
- `AC-US08-07` — связь Lesson / Student;
- `AC-US08-08` — future Lesson;
- `AC-US08-09` — точная граница начала;
- `AC-US08-10` — in progress;
- `AC-US08-11` — completed;
- `AC-US08-12` — cancelled;
- `AC-US08-13` — перенос до нового времени;
- `AC-US08-14` — перенос после наступления нового времени;
- `AC-US08-15` — чужой Lesson;
- `AC-US08-16` — not found;
- `AC-US08-17` — invalid value;
- `AC-US08-18` — API error;
- `AC-US08-19` — loading / duplicate protection;
- `AC-US08-20` — повторное открытие;
- `AC-US08-21` — persistence;
- `AC-US08-22` — unknown value;
- `AC-US08-23` — authentication / authorization;
- `AC-US08-24` — Frontend ↔ Backend E2E;
- `AC-US08-25` — отсутствие ложного UI-state;
- `AC-US08-26` — regression.

Если хотя бы один обязательный Acceptance Criterion имеет статус `FAIL`, итоговый статус US-08 не может быть `PASS`.
