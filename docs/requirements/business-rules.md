# Бизнес-правила и открытые решения

[К справочнику](../README.md) · [Scope / AC Sprint 1](../sprints/sprint-01/scope.md) · [API](../api/contracts/sprint-01.md)

## Формат и статус

BR-ID стабилен и не переиспользуется. Для каждого правила фиксируются статус, формулировка, источник и проверка. «Подтверждено для Sprint 1» — требование к результату, не статус реализации. Технические соглашения имеют канонические источники в архитектуре / API, не создают отдельные бизнес-правила без доменного смысла.

## Активные правила

### BR-01 — Автор создания занятия

**Статус:** подтверждено для Sprint 1.

Lesson может создавать только аутентифицированный Teacher.

Созданный Lesson принадлежит Teacher, который выполняет операцию создания. Teacher не может создавать Lesson от имени другого Teacher.

Идентификатор автора Lesson не выбирается пользователем отдельно при создании занятия.

**Источник / проверка:** [US-01 / AC-01](../sprints/sprint-01/scope.md#us-01--создание-занятия), [API-05](../api/contracts/sprint-01.md#api-05--создать-lesson).

Проверить:

- без аутентификации создание Lesson недоступно;
- пользователь без роли Teacher не может создать Lesson;
- Teacher не может указать другого Teacher в качестве автора;
- созданный Lesson связан с Teacher, выполняющим операцию.

Технический способ определения текущего Teacher задаётся правилами аутентификации и API-контрактом.

### BR-02 — Выбор ученика

**Статус:** подтверждено для Sprint 1.

Teacher может создать Lesson только для существующего Student, с которым у него существует связь Teacher–Student.

Student без связи с текущим Teacher не является допустимым участником создаваемого Lesson.

Связь Teacher–Student должна существовать на момент создания Lesson. Получение Student ранее в списке доступных учеников само по себе не гарантирует допустимость последующего создания: при выполнении операции правило проверяется повторно.

**Источник / проверка:** [US-01 / AC-01](../sprints/sprint-01/scope.md#us-01--создание-занятия), [API-04](../api/contracts/sprint-01.md#api-04--доступные-ученики), [API-05](../api/contracts/sprint-01.md#api-05--создать-lesson).

Проверить:

- связанный с текущим Teacher Student доступен для создания Lesson;
- существующий Student без связи с текущим Teacher не позволяет создать Lesson;
- несуществующий Student не позволяет создать Lesson;
- список доступных Student содержит только Student, связанных с текущим Teacher;
- если допустимость Student изменилась между получением списка и созданием Lesson, Backend использует актуальное состояние связи при выполнении операции.

Конкретный HTTP-код и формат ошибки определяются API-контрактом и общей моделью ошибок.

### BR-03 — Данные и результат создания

**Статус:** подтверждено для Sprint 1.

Создаваемый Lesson должен быть связан:

- с Teacher, выполняющим создание;
- с выбранным допустимым Student;
- с моментом начала `starts_at`.

Для Sprint 1 `starts_at` является обязательной временной характеристикой Lesson. Длительность и момент окончания не являются обязательной частью минимальной модели Sprint 1.

Lesson создаётся только при успешном прохождении всех применимых проверок.

Если хотя бы одно обязательное условие создания не выполнено, новый Lesson не должен появиться в системе. Частично созданный Lesson не допускается.

**Источник / проверка:** [US-01 / AC-01](../sprints/sprint-01/scope.md#us-01--создание-занятия), [API-05](../api/contracts/sprint-01.md#api-05--создать-lesson).

Проверить:

- успешное создание формирует один Lesson с корректными Teacher, Student и `starts_at`;
- отсутствие или некорректность обязательных данных приводит к отказу в создании;
- нарушение BR-01 или BR-02 приводит к отказу в создании;
- при отклонённой операции новый Lesson не сохраняется;
- успешный результат позволяет клиенту получить данные созданного Lesson.

Конкретный состав request / response DTO, HTTP-коды и формат ошибок задаются API-контрактом.

Правила допустимого значения `starts_at` относительно текущего времени определяются отдельно.

### BR-04 — Принадлежность занятий ученику

**Статус:** подтверждено для Sprint 1.

Student может просматривать только собственные Lesson.

При формировании списка предстоящих занятий система выбирает только Lesson, в которых текущий Student является участником.

Lesson другого Student не должен быть доступен через данный пользовательский сценарий.

Student не выбирает произвольного пользователя, для которого необходимо получить список занятий.

**Источник / проверка:** [US-02 / AC-02](../sprints/sprint-01/scope.md#us-02--просмотр-предстоящих-занятий-учеником), [API-06](../api/contracts/sprint-01.md#api-06--предстоящие-lesson-ученика).

Проверить:

- собственный Lesson текущего Student может попасть в результат при выполнении остальных правил выборки;
- Lesson другого Student не попадает в результат;
- изменение идентификаторов или параметров запроса не позволяет получить занятия другого Student;
- результат определяется текущим пользовательским контекстом, а не переданным клиентом идентификатором Student.

Технический способ определения текущего Student задаётся правилами аутентификации и API-контрактом.

Временной критерий того, какие Lesson считаются предстоящими, определяется отдельно в BR-05.

### BR-05 — Предстоящие занятия

**Статус:** подтверждено для Sprint 1.

Lesson считается предстоящим для Student, если его момент начала удовлетворяет условию:

`starts_at >= now`

где `now` — единый момент текущего времени, зафиксированный системой для выполнения конкретной операции выборки.

Lesson с `starts_at == now` считается предстоящим.

Lesson с `starts_at < now` не относится к предстоящим и не включается в соответствующий список.

В Sprint 1 принадлежность к предстоящим определяется только по моменту начала Lesson. Отдельное состояние «занятие идёт сейчас» не вводится, поскольку длительность и момент окончания не являются частью минимальной модели.

**Источник / проверка:** [US-02 / AC-02](../sprints/sprint-01/scope.md#us-02--просмотр-предстоящих-занятий-учеником), [API-06](../api/contracts/sprint-01.md#api-06--предстоящие-lesson-ученика).

Проверить:

- Lesson с `starts_at < now` исключается;
- Lesson с `starts_at == now` включается;
- Lesson с `starts_at > now` включается;
- все сравнения внутри одной операции используют одно и то же значение `now`;
- эквивалентные моменты времени с различными timezone offsets дают одинаковый результат.

Технические правила передачи, нормализации и сравнения времени определяются API conventions.

### BR-06 — Порядок предстоящих занятий

**Статус:** подтверждено для Sprint 1.

Предстоящие Lesson отображаются в хронологическом порядке по моменту начала:

`starts_at ASC`

Lesson с более ранним `starts_at` должен располагаться перед Lesson с более поздним `starts_at`.

Таким образом, ближайшие предстоящие занятия отображаются пользователю первыми.

Если несколько Lesson имеют одинаковый `starts_at`, их взаимный порядок не имеет отдельного продуктового значения. Техническое правило детерминированной сортировки для таких случаев задаётся API-контрактом.

**Источник / проверка:** [US-02 / AC-02](../sprints/sprint-01/scope.md#us-02--просмотр-предстоящих-занятий-учеником), [API-06](../api/contracts/sprint-01.md#api-06--предстоящие-lesson-ученика).

Проверить:

- Lesson с более ранним `starts_at` располагается раньше Lesson с более поздним `starts_at`;
- список из нескольких предстоящих Lesson отсортирован хронологически по возрастанию времени начала;
- наличие одинакового `starts_at` не нарушает согласованный технический порядок ответа.

### BR-07 — Календарная выборка

**Статус:** подтверждено для Sprint 1.

Teacher получает в календаре только собственные Lesson, относящиеся к выбранному календарному периоду.

Lesson относится к календарному периоду, если его момент начала удовлетворяет условию:

`from <= starts_at < to`

Начальная граница `from` включается, конечная граница `to` исключается.

Для корректного периода должно выполняться:

`from < to`

В Sprint 1 принадлежность Lesson календарному периоду определяется только по `starts_at`.

Длительность Lesson и пересечение интервалов не учитываются, поскольку момент окончания не является частью минимальной модели Sprint 1.

**Источник / проверка:** [US-03 / AC-03](../sprints/sprint-01/scope.md#us-03--календарь-преподавателя), [API-07](../api/contracts/sprint-01.md#api-07--lesson-в-календарном-периоде-teacher).

Проверить:

- Lesson текущего Teacher с `starts_at == from` включается;
- Lesson текущего Teacher с `from < starts_at < to` включается;
- Lesson с `starts_at == to` не включается;
- Lesson вне выбранного периода не включается;
- Lesson другого Teacher не попадает в результат;
- соседние периоды не дублируют Lesson на общей границе;
- диапазон с `from >= to` считается некорректным.

Технический формат `from` / `to`, timezone-aware transport, HTTP-код и формат ошибки задаются API conventions и API-контрактом.
