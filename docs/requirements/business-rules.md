# Бизнес-правила и открытые решения

[К справочнику](../README.md) · [Scope / AC Sprint 1](../sprints/sprint-01/scope.md) · [API](../api/contracts/sprint-01.md)

## Формат и статус

BR-ID стабилен и не переиспользуется. Для каждого правила фиксируются статус, формулировка, источник и проверка. «Подтверждено для Sprint 1» — требование к результату, не статус реализации. Технические соглашения имеют канонические источники в архитектуре / API, не создают отдельные бизнес-правила без доменного смысла.

## Активные правила

### BR-01 — Автор создания занятия

**Статус:** подтверждено для Sprint 1.

Lesson может создавать только аутентифицированный Teacher.

Созданный Lesson принадлежит Teacher, который выполняет операцию создания. Teacher не может создавать Lesson от имени другого Teacher.

Идентификатор автора Lesson не выбирается пользователем отдельно при создании занятия.

**Источник / проверка:** [US-01 / AC-01](../sprints/sprint-01/scope.md#us-01--создание-занятия), [API-05](../api/contracts/sprint-01.md#api-05--создать-lesson).

Проверить:

- без аутентификации создание Lesson недоступно;
- пользователь без роли Teacher не может создать Lesson;
- Teacher не может указать другого Teacher в качестве автора;
- созданный Lesson связан с Teacher, выполняющим операцию.

Технический способ определения текущего Teacher задаётся правилами аутентификации и API-контрактом.

### BR-02 — Выбор ученика

**Статус:** подтверждено для Sprint 1.

Teacher может создать Lesson только для существующего Student, с которым у него существует связь Teacher–Student.

Student без связи с текущим Teacher не является допустимым участником создаваемого Lesson.

Связь Teacher–Student должна существовать на момент создания Lesson. Получение Student ранее в списке доступных учеников само по себе не гарантирует допустимость последующего создания: при выполнении операции правило проверяется повторно.

**Источник / проверка:** [US-01 / AC-01](../sprints/sprint-01/scope.md#us-01--создание-занятия), [API-04](../api/contracts/sprint-01.md#api-04--доступные-ученики), [API-05](../api/contracts/sprint-01.md#api-05--создать-lesson).

Проверить:

- связанный с текущим Teacher Student доступен для создания Lesson;
- существующий Student без связи с текущим Teacher не позволяет создать Lesson;
- несуществующий Student не позволяет создать Lesson;
- список доступных Student содержит только Student, связанных с текущим Teacher;
- если допустимость Student изменилась между получением списка и созданием Lesson, Backend использует актуальное состояние связи при выполнении операции.

Конкретный HTTP-код и формат ошибки определяются API-контрактом и общей моделью ошибок.

### BR-03 — Данные и результат создания

**Статус:** подтверждено для Sprint 1. Lesson имеет Teacher, выбранного Student и момент начала starts_at. Backend проверяет запрос и сохраняет Lesson только при успехе; пользователь получает результат. В минимальный DTO не входят длительность и конец.

**Источник / проверка:** [US-01 / AC-01](../sprints/sprint-01/scope.md#us-01--создание-занятия), [API-05](../api/contracts/sprint-01.md#api-05--создать-lesson). Обязательные поля / связи проверяются; rejected request не сохраняет Lesson; успех подтверждается сохранением. Ограничения прошлого времени остаются Q-05, расширение длительности — Q-04.

### BR-04 — Принадлежность занятий ученику

**Статус:** подтверждено для Sprint 1. Предстоящие занятия выбираются только для текущего Student из аутентифицированного контекста.

**Источник / проверка:** [US-02 / AC-02](../sprints/sprint-01/scope.md#us-02--просмотр-предстоящих-занятий-учеником), [API-06](../api/contracts/sprint-01.md#api-06--предстоящие-lesson-ученика). Занятия другого Student не попадают в ответ, произвольный ID пользователя не управляет выборкой.

### BR-05 — Предстоящие занятия

**Статус:** подтверждено для Sprint 1, граница уточнена этой спецификацией. Upcoming Lesson удовлетворяет `starts_at >= now`. Равенство включено; `now` — один timezone-aware момент UTC, фиксируемый Backend при начале обработки запроса. Прошедшее занятие имеет `starts_at < now` и исключается.

**Обоснование:** включённая текущая граница не скрывает занятие в момент начала; единый снимок времени делает выборку и проверку детерминированными. Это определение по началу, не по окончанию: «уже идёт» не является отдельным статусом Sprint 1.

**Источник / проверка:** [US-02 / AC-02](../sprints/sprint-01/scope.md#us-02--просмотр-предстоящих-занятий-учеником), [API-06](../api/contracts/sprint-01.md#api-06--предстоящие-lesson-ученика). Проверить starts_at до, ровно на и после замороженного now, включая эквивалентные offsets.

### BR-06 — Порядок занятий

**Статус:** подтверждено для Sprint 1. Предстоящие занятия упорядочены по starts_at ASC. Технический tie-breaker `id ASC` делает результат стабильным при одинаковом начале, не задаёт продуктовый приоритет.

**Источник / проверка:** [US-02 / AC-02](../sprints/sprint-01/scope.md#us-02--просмотр-предстоящих-занятий-учеником), [API-06](../api/contracts/sprint-01.md#api-06--предстоящие-lesson-ученика). Проверить несколько времён и одинаковые timestamps.

### BR-07 — Календарная выборка

**Статус:** подтверждено для Sprint 1, границы уточнены этой спецификацией. Календарь выбирает только занятия текущего Teacher с `from <= starts_at < to`, где оба значения — абсолютные моменты и `from < to`.

**Обоснование:** полуоткрытый интервал исключает дубли на границе соседних периодов. Длительность не влияет на принадлежность периоду в минимальной модели; поиск пересечения интервалов не введён.

**Источник / проверка:** [US-03 / AC-03](../sprints/sprint-01/scope.md#us-03--календарь-преподавателя), [API-07](../api/contracts/sprint-01.md#api-07--lesson-в-календарном-периоде-teacher). Проверить точные границы, соседние периоды, чужого Teacher, разные offsets и неверный диапазон.
