# Аутентификация и авторизация API

[К API](conventions.md) · [Контракты Foundation](contracts/sprint-01.md#foundation)

## Контракт транспорта

Защищённый запрос передаёт `Authorization: Bearer <access_token>`. Frontend получает access token после входа и рассматривает его как непрозрачную строку. Конкретный формат, подпись, срок жизни и внутренняя структура не являются зависимостью UI.

Backend проверяет credential, находит Account и строит доверенный доменный контекст. Авторизация проверяет нужную роль и принадлежность / доступность ресурса. Account ID не заменяет Teacher ID или Student ID. Политика назначения и совмещения ролей требует Q-07.

Клиент не выбирает произвольный `teacher_id` / `student_id` для impersonation. В create Lesson поле `student_id` выбирает ресурс для занятия и проверяется по BR-02; текущий Teacher всегда получается из authentication context. В выборках `me` текущая роль тоже определяется сервером.

## Foundation и жизненный цикл

Регистрация и вход входят в минимальный F-06. API-границы описаны в контрактах; обязательные регистрационные сведения, идентификатор входа и выдача ролей заблокированы Q-07 / Q-08. Нельзя объявлять регистрацию готовой на основании одного endpoint path.

Пароль не хранится в открытом виде и не возвращается в DTO: Backend хранит проверяемый hash. Алгоритм и параметры, механизм токена, срок жизни и способ хранения токена клиентом выбираются владельцами в I-01 / I-02, с техническим ревью до соответствующей реализации. Отсутствие конкретной библиотеки не блокирует архитектуру или HTTP-формат, но этот выбор нельзя оставлять незавершённым при приёмке auth.

При отсутствии / невалидности / истечении токена возвращается 401 и общий код `authentication_required`; при неверных данных входа — 401 `invalid_credentials`, без раскрытия существования Account. Если Account определён, но не имеет нужного доменного контекста, — 403 `forbidden`. Правила ошибок — в [error model](errors.md).

Frontend при 401 защищённой операции прекращает использование недействительной сессии и предлагает вход. Ошибка credentials на форме входа остаётся ошибкой формы. 403 не запускает повторный login автоматически. Пароли и Bearer tokens не включаются в логи / доказательства QA.

## Границы Sprint 1

Восстановление пароля и подтверждение электронной почты исключены из спринта. Refresh token, серверный logout / revocation и расширенное управление аккаунтами не добавляются без отдельной задачи. Наличие слова Bearer не означает, что уже выбраны JWT, OAuth provider или хранилище токена браузера.
