# Общепроектные соглашения API

[К справочнику](../README.md) · [Контракты Sprint 1](contracts/sprint-01.md) · [Шаблон](../templates/api-contract.md)

## Baseline транспорта и имён

- Префикс всех прикладных маршрутов — `/api/v1`. Base URL окружения содержит origin Backend; префикс добавляет API-layer.
- JSON-тела запросов и ответов, кодировка UTF-8, `Content-Type: application/json`; клиент принимает JSON. Примеры — валидный JSON без комментариев.
- Поля и параметры на английском в `snake_case`. Ресурсные пути — lowercase, plural где применимо; `auth/login` и `auth/register` — явно названные операции.
- Request DTO содержит только объявленные поля; неизвестные body-поля отклоняются с 422. Это исключает незаметное принятие `teacher_id` для подмены текущего Teacher.
- Обязательность, тип и допустимость `null` определяются контрактом. Отсутствие, `null`, пустая строка и `[]` не взаимозаменяемы.
- ID — UUID-строки по [модели данных](../architecture/data-model.md). Сервер создаёт ID, Frontend не вычисляет доменные ID из Account ID.
- Успешный ответ — DTO или массив DTO, без общей `data`-оболочки. Список без элементов — 200 и `[]`, не 404. Пагинация не включена в Sprint 1.
- Защищённые операции используют [Authorization Bearer](authentication.md). Backend определяет текущий Teacher / Student из контекста, а не из произвольного параметра пользователя.

Правила здесь приняты как инженерный baseline для заданного стека. Они не добавляют новых функций в sprint scope.

## Даты и время

Каноническая семантика обмена:

1. Date-only: строка `YYYY-MM-DD`; не означает абсолютный момент.
2. Date-time: строка ISO 8601 с явным offset или `Z`, например `2026-10-05T10:00:00+04:00`. Naive date-time, Unix-числа и локализованные строки не принимаются вместо неё.
3. Backend переводит моменты в UTC для сравнения и ответа. Тот же пример возвращается как `2026-10-05T06:00:00Z`.
4. Допустимы секунды и дробные секунды до микросекунд; ответы могут опускать нулевую дробную часть. Сравнение выполняется по моментам, не лексикографически по строкам.
5. PostgreSQL хранит моменты с timezone-aware семантикой; детали в [модели данных](../architecture/data-model.md).
6. Frontend формирует абсолютное значение из ввода и явно выбранной / согласованной зоны; отображение может быть локальным. Нельзя выводить смысл зоны из подписи UI. Продуктовый выбор отображаемой зоны остаётся Q-10.

Для upcoming применяется BR-05; для календаря — BR-07. API диапазона получает два момента `from` и `to`, а не date-only. Необходим `from < to`. Конец исключён: соседние интервалы не показывают одно занятие дважды. UI переводит выбранные календарные даты в границы в согласованной зоне; переход суток / DST требует проверки и не заменяется прибавлением фиксированных 24 часов.

Проверка наличия timezone выполняется в Pydantic-схеме (например, timezone-aware тип плюс проверка строкового транспорта). Неверный формат — 422. Валидные моменты в неверном порядке — 400 `invalid_date_range`. Не вводить ограничения максимального диапазона без требования.

## HTTP-коды

| Код | Проектная политика |
| --- | --- |
| 200 | Успешное чтение / операция с телом, включая пустую коллекцию |
| 201 | Ресурс успешно создан |
| 204 | Успех без тела, только когда задан контрактом; в текущих контрактах не используется |
| 422 | Ошибка request schema: missing field, неверный тип / UUID / date-time / JSON, лишнее body-поле; обработка FastAPI/Pydantic |
| 400 | Семантически некорректный запрос с корректной схемой, например `from >= to` |
| 401 | Нет / недействительна аутентификация; `WWW-Authenticate: Bearer` |
| 403 | Account аутентифицирован, но роль / действие запрещены |
| 404 | Ресурс не найден; для недоступного Student при создании та же ошибка, без раскрытия чужого ресурса |
| 409 | Конфликт состояния только для явно определённого случая; не означает проверку пересечений расписания |
| 500 | Неожиданная серверная ошибка, в том числе неверный response DTO |

Коды сопровождаются [единой ошибкой](errors.md). Framework defaults не определяют проектный формат: Backend адаптирует обработчики ошибок и отражает их в OpenAPI. Ошибка сервера не классифицируется как клиентская 422.

## Что должен содержать контракт

Назначение и US / F; метод и путь; роль и аутентификация; path/query/body DTO с обязательностью, типами и ограничениями; успешный код и response DTO; проверки и BR; HTTP / доменные ошибки; парные примеры запроса и ответа; нерешённые вопросы с классом и влиянием. Неприменимые параметры явно помечаются отсутствующими.

Контракт с блокирующим решением не считается финальным, даже если путь уже выбран. Использовать [шаблон](../templates/api-contract.md). Изменения контрактов идут по [change management](../process/change-management.md); фактическая runtime-схема проверяется против этой спецификации после реализации.

Технические источники: [FastAPI — обработчики ошибок](https://fastapi.tiangolo.com/tutorial/handling-errors/), [Pydantic — timezone-aware datetime](https://docs.pydantic.dev/latest/api/types/#pydantic.types.AwareDatetime).
